# StartFlow 1.0.0 验证报告

验证环境：Windows 11 专业版 x64，10.0.26300，2026-10-19（用户时区 Asia/Shanghai）。SDK 10.0.402；自包含运行时 10.0.13；Inno Setup 7.1.0 x64。构建与测试工具版本固定在 global.json、脚本和 CI 中。

## 仍需用户或干净虚拟机人工回归

- 真正退出登录/重新登录；真实跨登录的“跳过一次”；睡眠唤醒与锁屏解锁。没有主动注销当前用户以免中断工作，策略与实际 --login 入口测试不能替代这些系统场景。
- 真实 UAC 弹窗取消/同意、受组织执行策略限制、无法访问的高权限进程、不同浏览器组合、Store 应用已运行去重。
- 系统设置即时切换主题事件、真实交互式语言切换后的每个对话框、200%/多显示器 DPI、键盘与屏幕阅读器的完整人工验收。
- 托盘各菜单、拖拽排序/多选/批量/导入导出对话框的完整人工回归（核心数据操作与存储已有测试）。
- 干净 Windows 11 账户的交互式安装、升级到不同目录、卸载提醒取消、系统禁用启动应用后的修复，以及便携目录不可写提示。
- 没有真实代码签名证书，不宣称 SmartScreen 信誉。GitHub 仓库及发行状态见 [项目主页](https://github.com/you2032zhu/StartFlow) 和 [Releases](https://github.com/you2032zhu/StartFlow/releases)，公开发布不替代上述人工验证。

复现步骤：在测试账户按教程构建 → 运行 `Build.ps1 -WindowsIntegration` → `Verify-Desktop.ps1` → 在没有已有 StartFlow 数据的账户运行 `Verify-Installer.ps1` → 使用临时无害目标按上列项目逐项操作并记录真实结果。安装验证脚本发现已有用户数据/启动项会拒绝继续。不要为了测试删除真实配置。

本报告将“自动化通过”“真实 Windows 观察/操作通过”和“尚未人工验证”分开。首版本地可用，不把尚未完成的人工覆盖称为全场景发布认证。
